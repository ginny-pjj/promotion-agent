## 二、实现思路

### 2.1 我对题目的理解

题目本质上是一个**推广申请处理 Agent**：每天把运营同学汇总好的申请信息，自动整理成负责人能直接用的结果。

我梳理下来，系统有 **3 类输入** 和 **2 类核心输出**：

**输入：**

| 输入 | 说明 |
|---|---|
| ① 抖加申请总结 | 群里的抖加汇总文本，包含博主、金额、支付人等 |
| ② 付款（垫付）申请总结 | 垫付汇总文本，包含达人、金额、打款人、日期等 |
| ③ 推广账号表（测试表格） | 公司已有的 Excel 主表，作为匹配和写入的基准 |

**输出：**

| 输出 | 说明 |
|---|---|
| ① 给负责人的简短汇报 | 汇总金额、明细条数、异常清单、处理结论 |
| ② 推广账号表测试副本 | 在原表结构基础上填入当天数据，**不修改原表** |

> 测试表格不是给 AI「读」的，而是业务结果的载体：负责人要在原来的账号、报价信息旁边，看到当天新增的抖加和垫付字段。

---

### 2.2 我现在的实现方案（MVP）

我目前完成的是一个**简单可执行版本**，核心形态是 **本地网页**：

```text
负责人在网页粘贴两类申请文本
        ↓
程序自动抽取字段（账号、金额、日期等）
        ↓
Python 规则校验（金额、笔数、日期、账号是否匹配）
        ↓
生成负责人汇报 + 测试表副本
        ↓
若有异常 → 标记「待人工确认」，生成人工确认单，不自动放行
```

**为什么先做网页，而不是直接接企业微信？**

- 先把「输入 → 处理 → 输出 → 异常标记」这条主链路跑通  
- 网页最直观，方便录演示视频、面试现场操作  
- 企业微信需要额外配置（群机器人 / 自建应用），我把它放在**下一阶段**，不影响当前 MVP 交付  

---

### 2.3 系统分层设计

我把 Agent 拆成 4 层，避免「什么都交给 AI」：

```text
┌─────────────────────────────────────────┐
│ 1. 抽取层（extractor.py）                │
│    从文本里提取结构化字段                  │
│    当前：正则解析（固定格式够用）           │
│    后续：可接 DeepSeek / 阿里云做兜底      │
└──────────────────┬──────────────────────┘
                   ↓
┌─────────────────────────────────────────┐
│ 2. 规则层（validator.py）                │
│    金额加总、笔数核对、日期异常、重复申请   │
│    账号是否在 Excel 中存在               │
│    ★ 这一层永远用代码，不用大模型          │
└──────────────────┬──────────────────────┘
                   ↓
┌─────────────────────────────────────────┐
│ 3. 人工确认层（human_review.py）          │
│    有异常 → 生成人工确认单，指派负责人     │
│    系统结论：暂不视为最终确认结果           │
└──────────────────┬──────────────────────┘
                   ↓
┌─────────────────────────────────────────┐
│ 4. 输出层（excel_writer + report.py）    │
│    写测试表副本 + 生成负责人汇报            │
└─────────────────────────────────────────┘
```

**我的核心原则：**

- **AI / 规则只负责「发现问题、整理信息」**
- **负责人负责「判断、确认、放行」**
- 涉及钱的计算和业务裁决，不能交给大模型拍板

---

### 2.4 「转人工」是怎么设计的（重点）

这是我特意想清楚的：**有问题不能自动过，必须有人接手。**

#### 什么情况会转人工？

| 异常 | 举例 |
|---|---|
| 笔数对不上 | 声明 7 笔，实际只识别 5 条 |
| 日期异常 | 预计打款日期早于申请日期 |
| 账号名对不上 | 文本写「渠工」，表里是「泵工」 |
| 金额/字段缺失 | 缺总额、缺打款人等 |

#### 转人工后发生什么？

1. 页面显示 **「已转人工确认」**，指派 `config/responsible.json` 里的负责人  
2. 生成 **《人工确认单》**（可下载 / 复制），列出全部异常  
3. Excel 测试副本里，相关行 **备注写「待人工确认」**  
4. 处理结论写：**「相关记录暂不视为最终确认结果」**

#### 负责人要做什么？

```text
收到人工确认单
    ↓
核对异常是否属实
    ↓
打开 Excel 测试副本，看「待人工确认」的行
    ↓
确认无误 → 进入正式业务流程
有问题   → 驳回，联系提交人修正
```

**系统不会自动点「通过」。** 这是我和 AI 讨论后定下的边界：Agent 是助手，不是审批人。

#### 当前 vs 后续

| 阶段 | 转人工方式 |
|---|---|
| **现在（MVP）** | 网页生成人工确认单 → **手动复制发给负责人** |
| **后续** | 接入企业微信自建应用 → **自动推送给指定负责人** |

---

### 2.5 测试表格的作用

很多人一开始会疑惑：测试表格是不是给 AI 看的？

我的理解是：**不是。** 它的作用是：

1. **匹配基准** — 用「抖音昵称」把文本里的博主/达人和表格行对应起来  
2. **结果载体** — 在原有业务字段旁边，填入当天的抖加、支付人、打款人、打款日期  
3. **安全副本** — 程序只读原表，写入新的测试副本，避免误改正式数据  
4. **人工核对入口** — 异常行备注「待人工确认」，负责人逐行检查  

流程：

```text
原始推广账号表（只读）
    ↓ 按昵称匹配
写入测试副本
    ↓
负责人检查副本 → 确认后再进正式流程
```

### 2.6 后续完整版规划

| 阶段 | 内容 |
|---|---|
| 已完成 | 网页输入、规则校验、汇报、测试表副本、人工确认单 |
| 下一步 | 企业微信自建应用，处理完自动推送给负责人（不需要内部群） |

| 长期 | 负责人确认/驳回留痕、OCR 截图输入 |

大模型接入时，**只替换抽取层**；金额校验、异常判定、人工确认机制保持不变。

## 三、遇到的问题

| # | 问题 | 我怎么处理的 |
|---|---|---|
| 1 | Excel 在 VS Code 里打开是乱码 | 认识到 `.xlsx` 是二进制，改用 Excel/WPS 查看；代码用 openpyxl |
| 2 | 飞书下载的表格文件名变成 `.xlsx.xlsx` | Windows 隐藏扩展名导致，手动改成正确文件名 |
| 3 | 生成测试副本时报错 | AI 写的 Excel 写入代码有 bug，改为给 Cell 赋 `.value` |
| 4 | 账号差一个字就匹配不上 | 增加 `unmatched_account` 检测，转人工而不是静默跳过 |
| 5 | 企业微信群机器人要建内部群，我没建成功 | MVP 阶段改为网页 + 手动发人工确认单；后续用自建应用点对点推送 |
| 6 | 项目文件夹看起来杂乱 | 清理 `web_output` 等运行产物；文档放 `docs/`，测试放 `tests/`，视频放 `demos/` |
| 7 | 演示视频文件过大 | demo-A 约 90MB，接近 GitHub 单文件上限，需压缩或放网盘 |

## 五、AI 生成了哪些内容，我做了哪些检查 / 修改

| 测试用例和示例数据 | `demos/` 下的 sample 文本 |

### 5.2 我自己做的关键判断和修改

虽然代码大部分是 AI 辅助写的，但以下决策和验证是**我主动做的**：

1. **定边界：AI 不能替负责人做「通过/不通过」**  
   - 我明确要求：有异常必须转人工，系统不能自动放行  

2. **理清 3 个输入的关系**  
   - 两类文本是「每天变化的输入」，测试表格是「相对固定的匹配基准」  

3. **用真实表格实测**  
   - 从飞书下载公司推广账号表，放进 `data/`，验证表头列、昵称匹配、写入是否正确  

4. **发现并推动修复 bug**  
   - 文件名双后缀、Excel 写入报错、测试副本生成失败等，都是我在实测中发现并让 AI 修的  

5. **决定演示范围**  
   - 录两个视频：A（笔数/日期异常）和 B（正常对照），够展示核心能力  
   - 暂不接企业微信，先把主流程做扎实  

6. **组织项目结构**  
   - 清理杂乱文件夹，把文档、测试、视频分到 `docs/`、`tests/`、`demos/`  

### 5.3 我对 AI 生成内容的检查方式

- 每写完一个功能，用 `demos/` 里的示例文本在网页跑一遍  
- 看输出是否符合预期：金额对不对、异常有没有标出来、Excel 有没有写入  
- 运行 `python -m pytest -q` 确认测试通过  
- 对「金额计算」「是否自动放行」这类关键点，坚持必须用 Python 规则，不接受 AI 估算
