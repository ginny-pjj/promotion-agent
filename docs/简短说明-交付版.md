## 三、实现思路

### 3.1 输入与输出

题目要求处理三类输入，产出负责人可用的结果：

| 输入 | 说明 |
|---|---|
| 抖加申请总结 | 每日抖加汇总文本（博主、金额、支付人等） |
| 付款（垫付）申请总结 | 每日垫付汇总文本（达人、金额、打款人、日期等） |
| 推广账号表（测试表格） | 公司 Excel 主表，用于账号匹配和结果写入 |

| 输出 | 说明 |
|---|---|
| 负责人简短汇报 | 汇总金额、明细条数、异常清单、处理结论 |
| 推广账号表测试副本 | 在原表基础上填入当天数据，**不修改原表** |

测试表格的作用：不是给 AI 看的，而是业务结果的载体——负责人需要在原有账号信息旁边，看到当天新增的抖加、支付人、打款人、打款日期。

### 3.2 整体流程

```text
网页粘贴抖加 + 垫付文本
        ↓
抽取字段（账号、金额、日期等）
        ↓
规则校验（金额、笔数、日期、账号匹配）
        ↓
生成负责人汇报 + 测试表副本
        ↓
有异常？ → 是 → 生成人工确认单，指派负责人，不自动放行
        → 否 → 进入常规抽查流程
```

### 3.3 为什么先做网页

我目前完成的是 **简单可执行版本**：本地网页输入、一键处理、下载结果。

选择网页的原因：
- 先把「输入 → 处理 → 输出 → 异常标记」主链路跑通  
- 方便录演示视频、面试现场操作  
- 不依赖企业微信配置，本地即可完整演示  

### 3.4 系统分层

| 层级 | 文件 | 职责 |
|---|---|---|
| 抽取层 | `extractor.py` | 从文本提取结构化字段（当前用正则） |
| 规则层 | `validator.py` | 金额、笔数、日期、重复、未匹配账号（**永远用代码**） |
| 人工确认层 | `human_review.py` | 有异常 → 人工确认单，不自动放行 |
| 输出层 | `excel_writer.py` + `report.py` | 测试表副本 + 负责人汇报 |

**原则：程序负责发现问题，负责人负责最终确认；涉及钱的判断不交给 AI。**

### 3.5 转人工设计

| 步骤 | 说明 |
|---|---|
| 触发条件 | 笔数对不上、日期异常、账号名不匹配、缺字段等 |
| 系统行为 | 生成《人工确认单》，指派负责人，Excel 备注「待人工确认」 |
| 系统结论 | 「相关记录暂不视为最终确认结果」 |
| 当前做法 | 网页复制 / 下载人工确认单，手动发给负责人 |
| 后续规划 | 接入企业微信自建应用，自动推送给指定负责人 |

### 3.6 后续完整版

- 企业微信：处理完自动把汇报和确认单推送给负责人  
- 大模型：文本格式不固定时，用 DeepSeek / 阿里云做字段抽取兜底（只替换抽取层）  
- 确认留痕：负责人确认 / 驳回状态记录

## 四、遇到的问题

| 问题 | 处理方式 |
|---|---|
| Excel 在 VS Code 打开乱码 | `.xlsx` 是二进制，改用 Excel/WPS 打开 |
| 表格文件名变成 `.xlsx.xlsx` | Windows 扩展名显示问题，手动修正 |
| 测试副本生成报错 | 修复 Excel 写入代码（Cell 需赋 `.value`） |
| 账号差一个字无法匹配 | 增加未匹配账号检测，转人工而非静默跳过 |
| 企业微信群需建内部群，未成功 | MVP 阶段改用手动发送人工确认单；后续用自建应用点对点推送 |
| 项目文件夹杂乱 | 清理运行产物；文档、测试、视频分目录存放 |
| 演示视频文件较大 | demo-A 约 90MB，接近 GitHub 上限，必要时压缩或放网盘 |

## 六、AI 生成了哪些内容，我做了哪些检查或修改

### AI（Cursor）主要生成的内容

- 项目代码骨架：`extractor.py`、`validator.py`、`excel_writer.py`、`web_app.py` 等  
- 网页演示界面（FastAPI + 前端）  
- 人工确认流转逻辑（`human_review.py`）  
- 企业微信推送模块（`wecom.py`，可选，当前未启用）  
- README、交付说明、示例文本  

### 我做的检查与修改

1. **定业务边界** — 明确要求：有异常必须转人工，系统不能自动放行  
2. **理清输入关系** — 两类文本是每日输入，测试表是匹配基准  
3. **真实表格实测** — 用飞书下载的推广账号表验证匹配与写入  
4. **发现并修复 bug** — 文件名、Excel 写入、测试副本生成等问题  
5. **选择演示范围** — 录制示例 A（异常）和 B（正常），覆盖核心场景  
6. **整理项目结构** — 文档、测试、视频分目录，便于交付  

### 我的验证方式

- 用 `demos/` 示例文本在网页逐条跑通  
- 核对金额、异常标记、Excel 写入是否正确  
- 运行 `python -m pytest -q` 确认测试通过

## 七、面试演示准备

### 演示内容（约 2–3 分钟）

1. 启动网页，粘贴示例 A，点「开始处理」  
2. 展示「已转人工确认」、人工确认单、异常清单

4. （可选）播放 `demos/demo-A-笔数与日期异常.mp4`  

### 核心代码讲解（任选一段）

| 文件 | 讲解要点 |
|---|---|
| `validator.py` | 如何用代码核对金额、笔数、日期，为什么不交给 AI |
| `human_review.py` | 有异常如何生成人工确认单、为何不自动放行 |
| `excel_writer.py` | 如何只读原表、按昵称匹配、写入测试副本 |

**一句话总结：**

> 这个 Agent 负责把申请文本整理成负责人能用的汇报和表格；发现问题会转人工，最终是否通过由负责人决定，不是 AI 决定。
