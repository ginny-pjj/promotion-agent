【推广申请处理 Agent — 口语版说明（精简版，可直接复制）】


一、实现思路

我做的是一个推广申请处理 Agent。每天会收到三类东西：抖加申请总结、垫付申请总结，还有一张公司一直在用的推广账号表（测试表格）。

我要的输出有两个：一是给负责人一份简短汇报，二是生成一张推广账号表的测试副本。测试表的作用不是给 AI 看的，而是让负责人在原来的账号、报价信息旁边，直接看到当天填进去的抖加、支付人、打款人这些信息。程序只读原表，只写副本，避免改坏正式数据。

实现上我分成四层：抽取（从文本拿字段，现在用正则）、规则校验（金额、笔数、日期、账号匹配，全部用代码算）、人工确认（有异常就不自动放行）、输出（汇报 + Excel 副本）。

目前是可执行的网页版本：打开页面，粘贴两段文本，点处理，就能看到结果。有问题的会转人工，生成人工确认单，指派负责人。没问题就走常规抽查。

后面完整版我想接企业微信，用自建应用把汇报和人工确认单直接推给负责人，不用建内部群。大模型我打算只放在文本抽取那一层，金额和是否放行仍然用代码，不交给 AI 拍板。


二、遇到的问题（3 个，面试好讲）

问题 1：把「预计打款」写成了「已经打款」

垫付文本里写的是「预计打款日期」，我一开始直接写进了 Excel 的「打款日期」列。这在业务上是两回事——预计不等于实际。如果自动化把计划当成已完成，负责人会误以为已经打款了。

我的改法：不再把预计日期写进「打款日期」；改写到备注里，比如「待人工确认；预计打款：2026-08-31」，等负责人核实后再进正式流程。

这个问题说明：Agent 不仅要「能写进去」，还要搞清楚每个字段在业务里到底代表什么。


问题 2：Excel 里日期显示成 46265，看起来像算错了

日期写进 Excel 后，打开看到的是 46265 这种数字，不是 2026-08-31。技术上这是 Excel 的日期序列值，但业务同事不懂这个，会以为程序算错了。

我的改法：写入 date 对象的同时，给单元格加上日期格式 yyyy-mm-dd，让人一眼能看懂。

这个问题说明：Agent 的输出是给业务同事看的，不能只追求程序没报错，还要考虑「人能不能看懂」。


问题 3：账号名差一个字，该自动匹配还是转人工？

文本里写「唐山第一女渠工」，表格里是「唐山第一女泵工」，差一个字就匹配不上。我可以强行做模糊匹配，但很容易写错行、填错钱。

我的选择：不匹配就报异常，转人工确认，让负责人决定对应哪一行，而不是让程序自己猜。

这个问题说明：Agent 要会判断——什么时候可以自动化，什么时候必须停下来问人。涉及钱的场景，宁可多一步人工，不能 silent fail 或乱猜。


三、使用了哪些 AI 工具

主要用的是 Cursor 的 Composer / Agent 模式，代码、网页、文档基本都是跟 Cursor 对话搭出来的。

DeepSeek / 阿里云 API 当前没有接入运行时，因为固定格式文本用正则就能演示全流程。Cursor 是开发助手，不是线上跑的业务组件。后续如果文本格式变乱，才考虑在抽取层加大模型兜底。


四、AI 生成了什么，我做了哪些检查 / 修改

AI 生成的：项目骨架（extractor、validator、excel_writer、web_app、human_review）、网页界面、文档初稿。

我自己做的：
1. 定边界——有异常必须转人工，系统不能自动放行
2. 用飞书下载的真实推广账号表做端到端测试
3. 用 Codex 做对抗测试，挖出上面 3 个问题并改掉
4. 决定演示范围——网页 + 两个演示视频（异常 / 正常）
5. 整理项目结构，把文档、测试、视频分到不同文件夹

验证方式：不是只看程序没报错，而是用示例数据反复跑，看 Excel 和汇报在业务上说得通不通。
